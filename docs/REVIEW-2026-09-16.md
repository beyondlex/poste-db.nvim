## Bugs fixed

1. **`session_conn.stop_all()` walked `pool` while deleting other keys**
   (`session_conn.lua`) — `M.stop()` removes every pool key sharing a
   connection URL (one URL, many databases), so calling it from inside
   a `pairs()` loop over the same table deletes keys other than the
   current one. That is undefined behavior in Lua and could silently
   skip live sessions on `:PosteDbSessionStop --all` / teardown. The
   keys are now snapshotted before stopping.

2. **AI code-block gate forced a confirm on every scoped read-only
   block** (`ai/actions.lua` `is_readonly`) — the keyword scan looked
   at the first token of the raw block, and `-- @connection x\nSELECT 1`
   (the exact header `append_header` writes, and which models copy back
   into replies) parsed its keyword from the comment → not read-only →
   confirm dialog for a plain SELECT. Leading comment lines are now
   stripped before the scan; a write hidden behind a leading comment
   (`-- cleanup\nDELETE …`) still flags. Test covers both directions.

## Recorded, not changed (with rationale)

- **`exec_run.strip_literals_and_comments` mishandles escaped quotes**
  (`'it''s'`) — the naive `'[^']*'` blanking can leave stray quotes and
  mis-blank, feeding the `is_query_sql` fallback classifier a slightly
  wrong string. The Rust side is the authoritative classifier; this is
  a last-resort heuristic for reconstructed responses. Fix together
  with the first misclassified real-world case.
- **`dml_guard.scan_text` re-runs the regex fallback after a clean
  tree-sitter pass** — TS finds nothing risky → `#hits == 0` → regex
  re-scans. The regex is strictly more conservative in normal cases
  (parens/string blanking only *removes* WHERE tokens), so the cost is
  an occasional extra confirm, never a missed one. Intentional safety
  direction, but worth knowing it is not a pure fallback.
- **`dml_guard.M.compute` reads only `trees[1]`** — injected-language
  trees are ignored. Fine for `.sql` buffers; would matter if the
  buffer ever gains injections.
- **`session_conn.on_session_stdout`'s no-newline branch can strand a
  complete non-result JSON event in the buffer** — it only clears the
  buffer when the trailing parse yields a `result`. Self-heals (the
  newline path parses and ignores non-result lines), and the session
  protocol currently emits only `result` events, so it stays latent.
- **`session_conn.stop()` never `jobstop`s a hung session** — it closes
  stdin and relies on the binary honoring EOF. A wedged binary would
  linger until nvim exit.
- **`QUERY_PREFIXES` in exec_run.lua vs Rust `QueryKinds` have drifted**
  (Lua's fallback set has CALL/EXEC/DESC; Rust's POSTGRES/SQLITE lists
  do not). The Lua set only breaks ties for reconstructed responses;
  flagging as mirror-drift per the docs/schema.md mirror rule.
- **`help doc vs code`: in sync.** All non-debug `:PosteDb*` commands
  and default keymaps match `doc/poste-db.txt` and the docs site;
  remaining gaps are debug-only commands hidden behind
  `setup({ debug = true })` (intentionally undocumented).
