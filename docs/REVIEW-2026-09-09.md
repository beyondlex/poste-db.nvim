Follow-up to `REVIEW-2026-09-06/07/08.md`. Scope: the modules that shipped
after the last round (tunnel, explain, edit_commit, exec_run) plus
connections, dml, export — then pattern sweeps for the known bug classes
(case-sensitive SQL keywords, and-or truncation, byte/display-width mixing,
timer handles). Baseline: 73 spec files / 1068+ tests green, luacheck
0 warnings / 125 files.

## Bugs fixed

1. **Lowercase `use db;` routed into the SQL session instead of switching
   context** (`exec_run.lua`, `sql_runner.lua`) — `detect_use` and
   `is_use_stmt` only matched uppercase `USE`, while `lex.find_use_database`
   (statusline/context) and the Rust binary are case-insensitive. With a
   resolved connection, a lowercase `use mydb;` therefore executed as real
   SQL in the persistent session — a syntax error on postgres/sqlite —
   where the uppercase form silently switches the context. Both matchers
   accept any case now. Tests: sql_exec_run_spec lowercase forms.

2. **`is_query_sql` classified `update … returning` by a case-sensitive
   substring find** (`exec_run.lua`) — lowercase `returning` (the common
   style; pg/sqlite return rows for DML+RETURNING) fell through to an
   affected-rows response, while an uppercase `RETURNING` *anywhere* —
   a string literal or comment included — flipped plain DML into a
   resultset. Literals/comments are stripped first and the keyword matched
   with word boundaries, case-insensitively. Tests: RETURNING cases plus
   the identifier/literal traps.

3. **A WHERE-less UPDATE was generatable from a cell edit** (`dml.lua`,
   `edit_commit/init.lua`) — `generate_update` emitted
   `UPDATE t SET …;` with no WHERE when the row had no primary key and
   every column value was NULL (nothing to match on): a single-cell edit
   became a full-table rewrite. `generate_delete` produced broken `WHERE ;`
   SQL for the same input. Both now refuse (return nil + reason),
   `generate_dml` skips and reports the reasons, and `commit_edits` shows
   what was refused — or "every edit was skipped" when nothing survived.
   Tests: sql_dml_spec refusal cases + skipped reporting.

4. **`:PosteDbExport [format] file [path]` ignored `path`**
   (`export.lua`) — `run(format, destination, path)` accepted the path and
   silently opened the interactive picker instead; completion only offered
   `clipboard` although the command/README advertise file|clipboard.
   `destination=file` now writes to the expanded path (directory created)
   or opens the directory browser when the path is omitted. Tests: file
   write via the command form, clipboard round-trip, first-resultset
   selection.

5. **A quoted port in connections.toml killed the connection picker**
   (`connections.lua`) — `format_connection` passed `conn.port` straight
   into `%d`; `port = "5432"` (a TOML string) threw "number expected"
   inside the picker callback. Coerced with `tonumber`, dialect default as
   fallback. Tests: sql_connections_spec string-port + formatting.

## Recorded, not changed (with rationale)

- **`sql_escape_val` renders control bytes as `\xHH` inside a plain
  quoted string** (export.lua) — that is not a SQL escape sequence: on
  postgres with `standard_conforming_strings=on` (the default) the value
  round-trips as the literal characters `\`, `x`, `H`, `H`. Control bytes
  in exported data are rare, and a correct fix needs per-dialect escape
  forms (`E'…'` for pg); not worth it today.
- **`explain.wrap_sql` refuses any statement containing `;`** — a
  semicolon inside a string literal is a false positive, but the failure
  direction is safe (EXPLAIN refuses to run).
- **`run_test_via_tunnel` blocks the UI up to 30s** — it shells out
  synchronously (`exec_run.run_sql` → `vim.system:wait`); acceptable for an
  explicit "test connection" action.
- **`build_response` counts a failed statement twice** (once from the
  event `status`, once from `result.error`) — `failed` only feeds the
  `has_error` boolean; no observable effect.
- **`edit_commit` on clickhouse stays per-statement greedy** (no
  transaction support) — documented in the code; partial application is
  possible there by design.
- **dml_guard TS→regex fallback, toml dotted headers, cursor dual-source**
  — carried unchanged from the 09-07 report.
- **plenary single-spec invocations are flaky in this environment**
  (`PlenaryBustedFile tests/sql/<one>.lua` sometimes reports
  `module 'poste.cli' not found` through the cache_loader even though the
  same file passes inside the full `tests/run.sh`). Always verify with the
  full suite; recorded so the next person doesn't chase it.
