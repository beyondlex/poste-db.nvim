Cross-repo review sweep (poste-ai.nvim → poste.nvim → this repo) focused on

## Fixed here (this change set)

1. **`toml.lua`: a literal-string backslash broke inline-comment stripping**
   — `strip_inline_comment` skipped 2 bytes after `\` in ANY string, but TOML
   literal strings (`'…'`) have no escapes; `password = 'a\'` followed by a
   trailing comment swallowed the closing quote and failed the whole parse
   with a bogus "Unclosed single-quoted string". The escape-skip now applies
   to basic (double-quoted) strings only. Also: a UTF-8 BOM made the first
   line fail as "Invalid key=value line"; it is stripped now.

2. **README contradicted the code on completion engines** — "Requires
   blink.cmp" while `completion/init.lua` ships a real nvim-cmp interface
   and `health.lua` probes both; the Requirements list already said
   "blink.cmp (recommended) or nvim-cmp".

3. **`docs/dev/sql/README.md` module index was missing seven modules** —
   explain / source_format / width / toml / tunnel / sql_log / snippets
   existed and are referenced from code and other docs but had no row.

## Fixed in the sibling repos during this sweep (contract-relevant here)

- poste.nvim `session`: a per-statement SQL error killed the whole `poste
  session` process (sqlite/pg/mysql paths). This is the failure mode behind
  "session exited (code …)" in `session_conn.on_session_exit`; the binary
  now reports statement failures as `status:"error"` events, which
  `session_conn.build_response` already handled.
- poste.nvim `to_url()`: full DIALECT_ALIASES normalization, sqlite
  query-string handling, db-segment percent-encoding — the Lua mirror in
  `connections.build_conn_url` was ahead on all three.
- poste.nvim `{{var}}` resolution: OS env > `.env` > env.json precedence
  (this repo's `get_env_vars` was the reference implementation).
- poste-ai.nvim: session-id RNG seeding (same-second instance collisions),
  dead call cleanup.

## Recorded, not changed (with rationale)

- **`exec_run.for_each_event` trusts jobstart's buffered elements to be
  complete lines.** With `--max-rows 0` the Rust side can stream very large
  resultsets; if nvim ever delivers a chunk split mid-line, that event
  fails `vim.json.decode` and is silently dropped. The Rust side always
  newline-terminates events, so this holds today; a concat-then-split
  (like `parse_lines`) would remove the assumption.
- **`sql_runner.lua` requires the same module twice under two names**
  (`state` + `sql_state`, lines 4–5). Both are used; harmless, just noise.
- Carried from prior reviews: `.idea/` and `connections.toml`/`.env` dev
  files in the repo root are working files for this repo's own playground,
  deliberately untracked-to-CI.

  `exec_run.detect_use` broad) is documented on both sides as intentional —
