## Fixes (each with tests)

- **A cursor on a blank line above a statement still executes it**
  (`statement.lua`). The binary maps a blank line to the blank itself
  (`context stmt` on line 2 of `SELECT 1;\n\n\nSELECT 2;` answers the
  0-based span (1,1)), so the forward skip to the next statement
  inverted the detected span: `stmt_start` landed on `SELECT 2;` while
  `stmt_end` still pointed back at the blank. The empty `stmt_lines`
  read as "all blank" and `<CR>` executed nothing for a buffer that had
  a perfectly good statement below the cursor — and `ts_stmt` would
  feed the same degenerate span wherever tree-sitter has no node for a
  line. When the skips walk `stmt_start` past `stmt_end`, the end is now
  re-derived with the same region-blind `;`-scan the Lua fallback uses
  (a `;` inside a literal, comment or dollar body does not bound it).
  The binary's (line,line) answer for a blank line is left as is: the
  Lua side is the only consumer, it now defends, and `stmt-ranges`
  already refuses to report blanks as statements.
- **`tests/run.sh` stops racing the user's nvim on ShaDa** (`run.sh`,
  `run_one.sh`). The exit-1 flakiness had a SECOND mechanism: two
  headless nvims sharing the real XDG state dir (a concurrent suite, the
  user's own editor) stale-lock the `qa` ShaDa write and E138 makes the
  runner exit 1 with every test green. STATE and CACHE now run isolated
  and `qa!` skips the ShaDa write entirely, like the poste-redis runner.
  XDG_DATA stays real ON PURPOSE, unlike redis: the tree-sitter sql
  parser the boundary specs read lives there, and hiding it (as
  `run_one.sh` had silently done all along — its targeted runs of that
  spec were always red) failed statement_indicator's boundary-gutter
  specs with "no Tree-sitter sql parser". Those specs' async fetch waits
  also grow 500ms/200ms to 2s/1s: the 500ms budget failed two specs once
  under build load.
- **`extract_stmt_at_cursor`'s fallback `else` is no longer nested
  inside the branch it pairs with** (readability only, no behavior). The
  `if stmt_start then … else` — ts/rust vs the Lua `;`-heuristic — was
  indented inside the directive-skip `while` loop, reading as part of it.
- **`tests/run.sh` exits 0 reliably** (`sql_editor_ui_spec.lua`). The
  datetime-refusal test deliberately walks `apply_typed_edit`'s
  validation-error path, which raises an ERROR-level notify; in headless
  nvim that prints "Error in command line: …", and when the deferred
  print landed inside the runner's `qa` window the process exited 1 with
  every test green — reproduced roughly 1-in-3 full runs (pre-existing
  flakiness, not introduced by anything above). The specs assert on the
  recorded cell error, not the notification, so `vim.notify` is captured
  for the describe.

## Probed, held (recorded on purpose)

- **`dml.quote_val`'s MySQL ISO-8601 rewrites miss minute-precision and
  non-UTC-offset spellings** (`2024-01-01T10:00Z`, `…T10:00+05:30` —
  only full seconds forms are rewritten). MySQL rejects the `T…Z` shape,
  so such a cell commits to a syntax error rather than a wrong value —
  fail-loud, and the renderer shows full seconds anyway. Held.
- **`editor/cell.track_cell_edit` compares JSON cells by reference** —
  re-entering an identical JSON document still marks the cell modified,
  and `<leader>w` then ships a no-op UPDATE (affected-rows verification
  flags it). Cosmetic; held.
- **`import/format.parse_csv` accepts an unterminated trailing quote** —
  the last field keeps the bytes after the opener. python-csv behaves
  the same way on read; the importer is paste-driven and errors loudly
  downstream on column mismatch. Held.
- **CI's test step swallows failures** (`run.sh || echo warning`) — the
  suite here passes WITH the dev binary present; whether it is green in
  the CI image (no binary) is what the shield guards. Making it strict
  needs that verified first. Held.
- Rust-side probes (`context detect/stmt/stmt-ranges` on unterminated
  literals, dollar bodies, out-of-range offsets, empty input, non-UTF-8
  stdin) all answered sanely or errored in a way the Lua callers already
  fall back from — recorded in poste.nvim's round-21 review.
