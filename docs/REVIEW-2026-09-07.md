# Code Review — 2026-09-07

Scope: full test-suite baseline (71 spec files, 1051 tests, all green), then
a luacheck-driven pass over `lua/poste-db/` (46 warnings → 0) with manual
verification of every warning site (per LEARNINGS #1: a warning is a
hypothesis, not a verdict), plus targeted logic review of dml_guard.lua,
toml.lua and the completion/introspect paths.

## Bugs fixed

1. **`--dialect` never passed to `context detect`** (`introspect/init.lua`) —
   `detect_target_at` built a `dial` flag string but never included it in the
   `vim.system` arg list, so dialect-aware function filtering silently fell
   back to generic (e.g. MSSQL/MySQL builtins missing from completion
   candidates). Args are now built conditionally. Flagged by luacheck
   ("variable dial is never accessed").

2. **`:PosteDbDiag` always reported `alias_map: nil`** (`commands.lua`) —
   `X and f(...) or {}` truncates the multi-value return, so the second
   return of `get_tables_and_alias` never landed. Resolved through an
   explicit function binding. (The `and-or` idiom strikes again — see
   AGENTS.md "Lua Pitfalls".)

3. **DB-browser select fields degraded to free-text input**
   (`db_browser/forms.lua`) — on `<CR>`, a field with `kind = "select"` and a
   `choices` list opened plain `vim.ui.input`, ignoring the choices entirely;
   a user could type arbitrary values into a constrained field. The `t` key
   already had the proper `vim.ui.select` picker — `<CR>` now uses the same
   flow. (Found via two shadowed locals: the residue of the half-finished
   branch.)

4. **Paste-copy had no cancel** (`db_browser/copy_progress.lua`) —
   `show_paste_progress` built and returned a cancel handle, but no caller
   ever wired it. The progress dialog now binds `c` (stops scheduling new
   jobs after the in-flight one, closes the dialog, shows a `[c] cancel
   remaining` hint); plain `q` keeps close-but-continue semantics.

## Recorded, not changed (uncertain / deliberate)

- **`dml_guard.scan_text` falls through to `regex_scan` even when
  tree-sitter parsed fine and found nothing** — the two classifiers agree on
  every case I enumerated (comments, quoted literals, subqueries, CTEs), but
  the design means a regex false-positive could surface even when TS cleared
  the statement. Spot-checked dml/dml_guard specs; no disagreement found.
  If one ever appears, gate the fallback on "TS unavailable / parse failed".
- **`toml.lua` does not support dotted section headers** (`[a.b]` becomes the
  literal key `"a.b"`) and TOML `_` digit separators stay strings. Documented
  minimal scope; connections.toml doesn't use either.
- **`statement.lua` swallows CLI stderr** in `extract_stmt_at_cursor` /
  stmt-ranges — now logged via `poste-db.log` at WARN, still returns nil to
  callers (changing the return contract felt too broad).
- **`buffer/nav.lua` cell-cursor pcall result is intentionally discarded**
  (both branches proceed on failure); the capture, not the semantics, was
  the smell.
- **`session_conn.lua` / `dataset.lua` cursor dual-source** — re-confirmed
  LEARNINGS #1's revision ("暂不做"); not re-litigated.
