## Bugs fixed

1. **`dml.quote_val` fired the `__expr:` SQL escape hatch on imported
   data** (`dml.lua`) — any CSV/JSON cell whose value starts with
   `__expr:` was emitted as RAW SQL by `generate_insert`, so a crafted
   (or careless) import file executed arbitrary statements with the
   connection's privileges. The hatch is an editor feature (the user
   types it into the cell editor; `editor/nav.lua`'s
   "__expr:CURRENT_TIMESTAMP" depends on it), so `generate_insert` /
   `generate_update` now take `allow_expr` — default FALSE — and
   `generate_dml` (the editor's only entry) passes `true`. The import
   path keeps the default: a `__expr:` cell imports as the literal
   string. Specs pin both directions plus the WHERE-value path.

2. **`export.sql_escape_val` emitted `\xNN` for control bytes in SQL
   INSERT exports — a form no dialect parses** (`export.lua`).
   PostgreSQL (standard_conforming_strings on, the default) stores the
   four characters verbatim, MySQL drops the backslash (`\x01` → `x01`),
   SQLite keeps the literal text: every exported value carrying a control
   byte re-imported corrupted on all three dialects. Now dialect-aware:
   postgres gets an `E''` literal with `\xHH` escapes (printable and
   correct); mysql/sqlite embed the raw byte, the only form that
   round-trips there. The old spec pinned the buggy output; updated to
   pin the dialect-aware one.

3. **`catalog.view_body_from_ddl` was case-sensitive and ungated**
   (`db_browser/catalog.lua`) — sqlite_master stores the statement
   exactly as written, so a view created as `create view v as …`
   (lowercase is common) sailed through the `%sVIEW%s` scan, and the
   paste engine composed `CREATE VIEW x AS create view v as …` — invalid
   SQL on the target. Matching is now case-insensitive AND only runs when
   the text starts with CREATE, which also protects a bare
   pg_get_viewdef body that merely contains the words `view … as` inside
   a literal. A new catalog spec covers the pure builders and row parsers
   (the module had none).

## Recorded, not changed (with rationale)

- **QUERY_PREFIXES mirror drift (carried from 09-16) is now annotated at
  the definition** (`exec_run.lua`): the flat Lua list is a documented
  superset of the Rust per-dialect `QueryKinds` (CALL/EXEC have no Rust
  counterpart), used only as a last-resort tie-breaker for reconstructed
  responses. The comment forbids promoting it to an authority.
- **`build_conn_url` (display+resolve) accepts a `url` field without
  scheme validation** — unlike poste-redis's resolver, which requires a
  known scheme prefix. The Rust binary validates on connect, and the
  error surfaces there; adding Lua-side validation would duplicate the
  dialect list for little gain.
- **export `sql_escape_val` cannot round-trip a NUL byte on
  mysql/sqlite** (raw NUL inside a quoted literal) — unreachable from
  PG/MySQL TEXT columns in practice (both forbid NUL in text), and
  SQLite-only NUL data would need `char(0)` concatenation.
- **export `format_json` label says "pretty-printed" but
  `vim.json.encode` emits compact JSON** — the FORMATS picker label
  overpromises; left as-is since the data is correct and a pretty
  printer is a feature, not a fix.
