## Fixes (each with tests)

- **`is_ddl` matches the keyword in any case** (`sql_runner/response.lua`).
  The exact-case `^CREATE%s`-style match missed every lowercase DDL —
  and the db-browser's own CREATE TABLE template
  (`db_browser/operations.lua`) inserts lowercase `create table`, so a
  statement written from the family's flagship flow never ran
  `completion.data.clear_cache()` nor `sem.invalidate()`: the new table
  stayed absent from completion and kept being reported "Table not
  found" by semantic diagnostics until some uppercase DDL or a restart
  happened by. SQL keywords are case-insensitive; the match now folds
  the first real line once. The spec gains the lowercase/mixed-case
  forms plus two keyword-prefix identifiers (`created_at_ts t;`,
  `alphabet soup;`) that must stay non-DDL.
- **A commit that touched MORE rows than edits is flagged**
  (`edit_commit/exec.lua`). `commit_outcome` compared only
  `affected < expected`, so the no-primary-key fallback's all-column
  WHERE matching duplicate rows — one UPDATE editing 2+ rows —
  classified as a clean commit. The over-direction is the mirror of the
  partial case and just as much a warning: the user asked to change one
  row and the database changed several, silently. It now returns
  `partial` with a duplicate-rows message, riding the existing WARN
  notify and the journal's `!` mark.
- **One corrupt journal line cannot take the log viewer down**
  (`log_viewer.lua`). `sql_log.jsonl` lives in the user's data dir and
  `load_entries` accepted any decodable JSON, so a hand-edited line — a
  numeric `ts`, an object `error`, a bare `42` — crashed the whole
  render: `format_time` indexed a number, `filter_matches` indexed a
  non-string field, the ts sort indexed a non-table. The load seam now
  normalizes every entry: the string fields the viewer reads coerce
  (numbers/booleans via `tostring`, tables/userdata drop as unreadable),
  a non-number `elapsed_ms` drops before `%5s` renders a table address,
  and a line that is not an object is skipped. `_set_entries` runs the
  same seam so specs exercise what the disk load does; `format_time`
  also refuses non-strings directly.
- `db_browser/flash.lua`'s level doc refreshed (the facade passes
  `vim.log.levels` INFO/WARN = 2/3, not "0 (info)") — comment only.

## Probed, held (recorded on purpose)

- **The journal filter now matches `entry.error` text too**
  (`log_viewer.filter_matches`). The detail-highlight pass already
  marked filter matches on error lines — searching for the reason
  ("Timeout", "does not exist") was *meant* to find entries, but the
  field list (table/connection/status/database/source/sql) filtered
  the list down to nothing instead, which read as a broken filter. The
  error text completes the field set the viewer's own UX promises.
- **`_rerun_lines` on SQL with a trailing newline emits a spurious
  trailing blank buffer line** (`"SELECT 1;\n"` → `{ "SELECT 1;", "" }`).
  The writer (`sql_log.format_entry`) stores statements without a
  trailing newline, so no live path produces it. Held.
- **`guess_table` matches JOIN/FROM inside literals and comments**
  (`'join users'` in a WHERE string, `-- from hell` in a comment) — the
  documented heuristic class; the binary-backed `extract_table_name` is
  what the dataset tabs use. Held.
- **`preview_sql` on a leading-blank-line SQL returns the bare
  ellipsis** (`"\nfoo"` → `"…"`) — a summary row of one character.
  `clean_sql` trims real entries before the preview sees them. Held.
- `semantic_diagnostics` re-read end to end (the dotted-reference
  destructuring, the per-database `ref_db` tie logic, the jobsettle
  contract, the catalog exemptions) — nothing new to flag; the
  schema-vs-database conflation for postgres two-part refs remains the
  known, documented limitation.
- `highlights/render.find_cell_range_scan`'s `seps[col] + 2` was
  suspected of splitting the 3-byte `│` separator — it is the 0-based
  column of the space after it, byte-identical to the `col_starts`
  primary path. No change.
- `width.lua`, `completion/ctx.lua`, `buffer/header.lua` (the
  header-index/padding pairing), `db_browser/notify.lua` — read, no
  findings.
