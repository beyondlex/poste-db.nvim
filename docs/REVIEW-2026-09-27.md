Round 42, following `docs/REVIEW-2026-09-26.md`. Scope: adversarial probing
of the pure-function surfaces with unusual data — `toml`, `import/format`,
`import/mapping`, `connections` (env resolution, URL building), `statement`
(table extraction, labels), `dml`, `ident`, `width`, `format` — driven by a
throwaway probe spec (`PlenaryBustedFile`, since removed); everything that
survived is either pinned as a test or recorded below.

Baseline: 1876/0 over 114 spec files. Final: **1886 Success / 0 Failed /
0 Errors** over 114 spec files, luacheck clean.

## Fixes (each with tests)

- **`statement.extract_table_name` let an escaped-quote literal forge the
  table name.** The literal blanker was the pattern `'([^']|'')*'`. A greedy
  `[^']` that had already passed a `''` escape only stops at the next quote
  it sees — which is the *following* literal's opening quote. `'it''s',
  'note from bob'` matched as `'it''s', '` and left the second literal's
  text visible to the keyword scan:
  - `SELECT 'it''s', 'note from bob' FROM users;` extracted **"bob"**
  - `update t set a = 'it''s a note from 2024', …` extracted **"2024"**
    (the fake `from` outranked the real `UPDATE`, which is scanned second)

  The wrong name flowed into the dataset tab meta (the `sql` export's
  INSERT target and the edit-commit journal). Replaced with
  `blank_single_quoted`, a scanner that ends each literal at its own
  unpaired quote, blanks an unterminated one through end-of-input, and
  stays byte-length-preserving (`clean`/`upper` share offsets).

- **`toml` parsed `[a] [b]` as section `a` and silently dropped `[b]`.**
  Every key after it landed in the wrong connection; a shared
  connections.toml that carries postgres and redis sections would have
  had the redis one vanish. The text after the closing bracket must now
  be empty or a comment — the rule the quoted-header path already had.

- **`toml` unquoted `"""x"""` into the garbage value `""x""`.**
  Multi-line strings were documented as unsupported, but the failure mode
  was silent corruption of whatever host or password was written that
  way. Now a named error, like `[[array-of-tables]]` and dotted keys.

- **`import.format.parse_json` rejected a bare JSON object** with the
  misleading "JSON array is empty". A pasted API response (`{"a":1}`)
  now imports as one row, exactly like `[{"a":1}]`; an object with no
  keys at all still errors.

- **`import.format.parse_csv`/`parse_tsv` accepted a duplicated header
  name** (`a,a`). The column map pointed both file columns at one table
  column and whichever came last silently won. Now fails naming the
  column.

## Observed, left alone (each verified, none actioned)

- **Duplicate `[section]` headers merge key-by-key.** Spec-correct TOML
  errors; this parser merges and last-wins. Erroring would take down the
  whole config (every connection, plus the statusline that reads it) over
  a copy-paste slip; merging at least keeps working. Revisit only if a
  user hits it.
- **A top-level scalar sits beside the sections** (`dialect = "postgres"`
  above the first header). Every consumer already guards with
  `type(entry) == "table"`, so it is inert.
- **`tonumber` accepts hex but not `1_000`/`0o17`/`inf`.** Mixed support,
  but every miss fails closed: `port = 1_000` becomes the explicit
  "port must be a number between 1 and 65535" error, not a bad URL.
- **`ident.quote("")` returns the empty string.** Reachable only from a
  bug elsewhere (the DML builder refuses an empty table name first); the
  database would reject the empty identifier anyway.
- **`mapping.coerce_value` keeps `1e5` as text even for a numeric
  column.** The digit-string gate is `^-?%d+%.?%d*$`; the file's `1e5`
  then inserts as the quoted literal `'1e5'`, which postgres rejects for
  an integer column. Widening the gate needs a real TOML-number-grammar
  decision, and the per-row error the server returns already names the
  offending row.
- **`csv_escape` does not neutralize spreadsheet-formula injection**
  (a cell `=cmd|' /C calc'!A0` round-trips verbatim). The exporter's job
  is fidelity, not guarding whatever opens the CSV later; flagging would
  corrupt legitimate `=…` text.
- **`width.truncate` (nvim mode) measures each character in isolation**,
  so a combining mark counts its standalone width even though
  `display_width` in the same mode folds it. This is the documented
  two-oracle design (see the module header), not drift.
