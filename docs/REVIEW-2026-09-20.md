## Bugs fixed

1. **A `[section]` without a `dialect` crashed every resolution of it**
   (`lua/poste-db/connections.lua`) — the `is_sql_dialect` gate
   deliberately allows a nil dialect ("defaults behave like postgres
   elsewhere" per the constants doc), but `build_conn_url` then
   concatenated the nil scheme (`attempt to concatenate a nil value`);
   with the scheme defaulted, the port fallback also read the nil
   dialect. The default is now real: `scheme = conn.dialect or
   "postgres"` and the port fallback reads the same normalized scheme.
   Pinned by a spec case (`legacy = { host = …, database = … }` resolves
   to `postgres://old-db:5432/main`).

## Contract work (landed in poste.nvim, verified from here)

- **The Rust connection store now reads `connections.toml`** (poste.nvim
  REVIEW-2026-09-20, item 2). Until today `:PosteDbConnection` → Test and

## Recorded, not changed (with rationale)

- **`ssl_mode` is a dead field on both mirrors** — Lua's `build_conn_url`
  ignores it, Rust's `to_url()` ignores it (Rust merely parses it since
  today). Nothing documents it, so nothing misbehaves; honoring it for
  postgres would change resolution behavior and belongs to a deliberate
  cross-repo pass (recorded on the Rust side too).
- **`build_conn_url` does not percent-encode the host** — neither does
  Rust `to_url()`; IPv6 literals pass through raw on both sides. A host
  is DNS name/IP by construction; mirrors stay in sync.
- **`toml.lua` does not support multi-line (`"""`) or array-of-tables
  (`[[x]]`) forms** — out of its documented subset. Passwords/paths are
  single-line values; the Rust side (real `toml` crate) accepts the full
  grammar where it matters (`connection test`/`list`).
