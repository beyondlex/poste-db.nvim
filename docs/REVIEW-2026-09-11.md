# Code Review — 2026-09-11

Follow-up to `REVIEW-2026-09-06/07/08/09.md`. Scope: fresh read of
connections.lua / toml.lua / statement.lua / dml.lua / format.lua /
sql_runner.lua / exec_run.lua / export.lua / dataset.lua (sort

## Bugs fixed

1. **Error-box wrapping cut lines at byte offsets** (`format.lua`
   `wrap_text`) — `line:sub(1, width)` split multibyte characters in
   half; SQL error messages routinely contain non-ASCII (CJK table
   names, localized engines), so the results buffer received invalid
   UTF-8. Wrapping is now char-boundary + display-width based
   (strcharpart/strdisplaywidth, same approach as poste.nvim's
   `layout.word_wrap`). Tests: ASCII boundary, CJK never-split,
   mixed-message round-trip.

2. **A broken connections.toml re-read / re-parsed / re-logged on every
   call** (`connections.lua` `get_connection_config`) — the statusline
   calls this per redraw and completion per keystroke; a parse failure
   skipped the mtime-keyed cache entirely, so one broken file meant
   file I/O plus a WARN per redraw until fixed. Failures now populate
   the same cache; editing the file picks the fix up. Test: second call
   served from the failure cache (parse_file called once).

3. **CSV/TSV export corrupted on bare carriage returns**
   (`export.lua`) — `csv_escape` quoted only `" \n ,`, and the TSV
   cell cleaner replaced only `\t \n`: a value containing a bare CR
   broke the record structure of the exported file. CR now triggers
   CSV quoting and is replaced with a space in TSV. Tests: CR quoting,
   CR→space in TSV cells.

4. **`sql_escape_val` echoed values into the log** (`toml.lua`) — an
   unclosed-string parse error embedded the raw value in the message
   that goes to `state.log`; connections.toml values are frequently
   secrets. The message now names the problem without the value.

Also cleaned `extract_table_name`'s `find("JOIN", idx, {plain=true})`
to a plain `true` — LuaJIT coerces any non-nil 4th arg to truthy so the
behavior was accidentally right, but the table read like a different
API (behavior-identical, covered by the existing suite).

## Recorded, not changed (with rationale)

- **JSON export loses duplicate column names** (`SELECT a.id, b.id`)
  — inherent to JSON objects; CSV/TSV/Markdown keep both columns.
  Worth a `name_2` suffix only if it ever bites someone.
- **`resolve_connection_url` appends `?mode=rwc` to sqlite paths even
  when the path already carries a query string** — unknown for real
  files; would produce an invalid URL only in that case.
- **`export_to_file`'s atomic rename uses `os.rename`** — on Windows
  `rename()` may fail when the destination exists, leaving the `.tmp`
  sibling; macOS/Linux (this repo's platforms in practice) are fine.
- **toml.lua remains a minimal parser**: no multi-line strings/arrays,
  no quoted keys, dotted section headers treated as flat names — all
  carried from earlier rounds and adequate for connections.toml.
- **`compute_view_indices` sorts NULLs last in both directions**
  (postgres flips NULL-first on DESC) — deliberate UI choice; the
  comparator itself checks out for strict weak ordering across mixed
  number/numeric-string/boolean/NULL cells.
- Carried unchanged from the 09-09 report: `sql_escape_val` control
  bytes as `\xHH`, `explain.wrap_sql` refuses any `;`,
  `run_test_via_tunnel` blocks up to 30s, dml_guard TS→regex fallback,
  toml dotted headers, plenary single-spec invocations flaky.
