## Bugs fixed

1. **A quoted header behind whitespace kept its quote characters**
   (`toml.lua`, this round's first commit). The fast quote check on a
   `[section]` header inspects only the character right after `[`, so
   `[ 'local' ]` — legal TOML — took the unquoted path and stored the
   section under `'local'`, quotes included; `resolve` never found it
   under `local` and the connection silently vanished from every list.
   The unquoted path now strips a MATCHING quote pair (with
   `unescape_basic` for the double-quote form); a name whose ends merely
   look like quotes (`[a"]`) stays verbatim. Pinned by 2 tests in
   `sql_toml_spec`.

2. **Numeric underscores degraded the value to a string** (`toml.lua`,
   same commit). `port = 64_000` is a legal integer; plain `tonumber`
   rejected the `_` and the value arrived wherever it was used as the
   STRING `"64_000"` — a config that looked fine failing far from the
   typo with "expected an integer". The retry strips underscores and is
   guarded to fully-alphanumeric tokens, so `_10` and `foo_bar` stay
   strings and `1__0` (spec-illegal) does not coerce. Pinned by 2 tests
   in `sql_toml_spec`. The same fix landed in poste-redis's vendored
   copy, and a tail-diff confirms the two bodies are byte-identical
   apart from the vendored header.

3. **A host carrying its own port built a doubly-coloned URL**
   (`connections.lua`). `host = "localhost:5432"` — the
   connection-string habit — produced
   `postgres://localhost:5432:5432/db`, which only failed at the binary
   with a URL parse error naming nothing. Both the plain and tunnel
   paths now reject it with "move it to the `port` field", and a
   whitespace host is rejected the same way. Pure hex+colons still pass
   (IPv6 literals for `url_host`); a MSSQL named instance
   (`server\inst`, no colon) passes untouched and is pinned so. The old
   "brackets nothing that is not an IPv6 literal" test had
   `localhost:5432` in its pass-through list asserting the old behavior;
   it moved out of that list into its own rejection test. Pinned by 3
   tests in `sql_connections_spec` (67 → 71).

4. **`format_number` printed the full expansion of a huge float**
   (`format.lua`). A Float64 `1e300` fell through the `< 1e15` integer
   gate into `%.4f` and rendered ~300 digits, blowing the column width
   up with it. Every double at or above 1e15 magnitude is
   integer-valued, so what falls through past that gate is ±inf and
   magnitudes whose `%f` form is the full expansion — both now render
   `%.6g` (`1e+300`, `inf`; `nan` unaffected). Pinned by a test in
   `sql_format_bigint_spec`.

5. **`USE [My DB]` was cut at the space** (`lex.lua`). The canonical
   T-SQL spelling of a database with a space took the bare-name scan and
   came back as `[My`. Bracket-quoted names now read whole, including
   the doubled-`]]` escape, and an unterminated bracket returns nil like
   the other quotes. Pinned by 3 tests in `sql_lex_spec` (34 → 37).

6. **A kindless entry crashed `confirm_message`** (`dml_guard.lua`).
   `seen[r.kind] = true` with a nil kind raises "table index is nil";
   the API is exported and now skips malformed entries (with a generic
   fallback when nothing kind-bearing remains). Pinned by a test in
   `sql_dml_guard_spec` (37 → 38).

7. **`USE [My DB];` executed server-side but never switched the
   plugin's context** (`exec_run.lua`, landed after the doc's first
   pass). Item 5 fixed the context-scan side (`lex`); the EXECUTION side
   (`detect_use`, which synthesizes the use-response on the
   no-connection path) still only matched bare/hyphen/quoted names, so
   the canonical T-SQL spelling reached the server as real SQL while the
   plugin kept pointing at the old database. Bracket names now read
   whole (greedy to the last `]`, `]]` unwinds), with and without a
   trailing comment. Pinned by 3 tests in `sql_exec_run_spec` (40 → 42).

## Probed, held (recorded on purpose)

- `plan_resultset_layout` returning nil for an empty `results` array is
  by design (callers own the nil), and the adversarial shapes I threw at
  the renderers that mattered — ragged rows, huge cells, newline cells,
  mixed types, nil column names, map-shaped rows — all behave or fail
  closed once the input is in the documented `{ results = … }` shape.
- `snippet`/`ellipsize` never split a UTF-8 char (the cut backs up over
  continuation bytes) — CJK confirm snippets stay valid.
- `dml_verb` correctly ignores `TRUNCATE`/`DROP` (they are not this
  guard's class), flags lowercase `delete from t`, ignores a DELETE
  inside a string literal, and the `-- WHERE` comment does not satisfy
  the filter check (over-flag, never under).
- `csv_escape` quotes `\r`, `format_tsv` flattens `\t\r\n`,
  `format_markdown` breaks newlines to `<br>` and escapes `|`, and
  `sql_escape_val` keeps its dialect-specific control-byte rules — all
  re-driven with hostile cells.
- `connections.toml` tracked in git is a template: every secret field is
  a `{{VAR}}` and `.env` is gitignored (checked, not assumed).
- `type(val) == "blob"` in `cell_to_string` is dead (Lua has no blob
  type) — harmless, noted for a future cleanup rather than churned now.

## Architecture smells (recorded, not acted on)

- **`connections.toml` is tracked in git, and its `url` field accepts a
  full credential-bearing URL**. The template itself only carries
  `{{VAR}}` placeholders today, but nothing stops a future edit from
  pasting `url = "postgres://user:pass@host/db"` straight into a
  committed file — the gitignore protects `.env`, not this file. Worth
  a health-check warning when a tracked connections.toml carries a
  password-shaped `url`.
- **The vendored-copy pins go stale by design** (shared with
  poste-redis): the `toml.lua` header pins a poste-db commit that HEAD
  keeps outrunning on both sides. The tail-diff used this round is the
  cheap guard; noting it here so the next vendor-sync knows the command.
- **REVIEW logs accumulate under `docs/`** with multiple files per day
  (`REVIEW-2026-10-05.md` + `-round-54` + `-round-55`). Numbered rounds
  in ONE rolling file would halve the listing noise; cosmetic, recorded
  only.
