## Fixes (each with tests)

- **`lex.find_use_database` ate comments and cut quoted names**
  (`5eb970e`, `a9604f0`). The raw-line anchor handed whatever followed
  `USE` back verbatim: `USE /* default */ mydb` returned `/* default */`
  as the database, `` USE `my db` `` was cut at the space inside the
  quotes (`my`), and `USE mydb;-- note` kept the `;--`. The name is now
  read after skipping whitespace and line-local block comments, quoted
  names are taken between their quotes, and a bare name stops at
  whitespace or `;`. The new `lex.block_comment_depth_after` carries
  block-comment depth across lines so a line-by-line scanner knows it is
  inside a `/* … */` region (the next item's enabler).
- **A USE or directive inside a multi-line block comment no longer
  applies** (`ce38190`). `resolve_context` matched each line in
  isolation, so a commented-out block — `/*` / `use analytics` / `*/` —
  still switched the database for every statement below it, and a header
  directive wrapped in block comments counted too. Both phases now only
  match at block-comment depth 0; `--` line comments (the normal
  directive form) keep working.
- **`toml.lua`: a fully-quoted key or header is one name, dots and all**
  (`9516208`, `c23dc44`). This is round 39's recorded item. `"my.key" =
  1` died as a dotted key because the check looked at the raw key text;
  a fully-quoted key now unquotes (escapes respected) to a single name
  whose dots are its own, while bare `a.b` and quoted fragments
  `"a"."b"` keep the documented rejection. Quoted headers get the same
  treatment: `["my conn"]` used to store a section literally named
  `"my conn"` (quotes included) and `["a]b"]` was cut at the `]` inside
  the quotes by the first-`]` scan.
- **`import/format.parse_csv`: a stray quote mid-field no longer
  swallows the rest of the file** (`64a6fc9`). A quote flipped the
  scanner into quoted mode wherever it appeared, so an unescaped inch
  mark (`3" pipe,2`) swallowed the following commas and newlines into
  one giant cell until the import failed with a bogus "expected N
  columns" — or silently mis-aligned when the file happened to stay
  rectangular. A quote now only opens a quoted region at the start of a
  field (the RFC-4180 / python-csv reading); elsewhere it is literal
  data.

New specs: `sql_lex_spec` (24), `sql_import_format_spec` (20 — this
module previously had only transitive coverage); `sql_context_spec`
+5, `sql_toml_spec` +8.

## Verified clean rather than assumed

- **Block comments do not nest** in `is_comment_or_string`: the first
  `*/` closes them, which matches standard SQL — a probe expecting
  nesting semantics was wrong, not the scanner.
- The string region in `is_comment_or_string` spans **opener..closer
  inclusive**; positions outside a closed literal answer false even when
  the literal is unterminated at end-of-line.
- `block_comment_depth_after` ignores comment markers inside strings,
  respects backslash escapes in `'-strings but not in `` `-strings, and
  never leaks depth from a `/*` that sits after a `--` on the same line.
- `lex.find_block_for_line` returns the line AFTER the marker (the
  block containing the cursor starts there) — pinned, since my first
  test expectation guessed otherwise.

## Recorded, not changed (with rationale)

- **`USE mydb-- x` (glued `--`, no space) returns `mydb--`.** Whether
  the `--` starts a comment is dialect-dependent (MySQL requires `-- `;
  PostgreSQL accepts `--`), and the bare-name scan already stops at
  whitespace, so the common `USE mydb -- note` shape is correct. Left
  alone rather than guessing a dialect the line has not declared.
- **`layout.dynamic_line` budgets truncation in characters, not display
  columns** for `left`/`mid`/`right` truncation (`avail` counts chars),
  so a CJK-heavy string can overflow `container_width`. `word_wrap` IS
  display-width aware and `pad`/`cell` measure correctly; only the
  truncate paths are char-budgeted. Fixing means a display-width
  prefix walk — real, but layout-only cosmetics; queued rather than
  rushed.
- **`toml.lua` stores `"a" "b" = 1` under a key literally named
  `"a" "b"`** (two quoted fragments, no dot, so no rejection fires).
  Degenerate input with no connections.toml shape behind it.
- **`insert_hint.lua` strips `--`-to-EOL including inside string
  literals.** Both `full_text` and `text_offset` strip identically, so
  the cursor math stays self-consistent and the hint column search runs
  on the raw line; drift is bounded to lines with `'a--b'`-style values.
  Heuristic module with a documented debug switch — recorded.
