# Code Review — 2026-09-19

Follow-up to `REVIEW-2026-09-18.md`. Scope: the Lua modules untouched since
09-07 (statement/lex/ident/import/dml_guard/syntax/ts_stmt/nav, the
db_browser helpers and the buffer render path), a data-driven
`gsub`/`find` pattern sweep across `lua/poste-db/`, and the SQL-generator
surface after the 09-18 table_ops fix. Baseline: tests green
(1268 → 1276 with this pass's additions), luacheck 0 warnings / 225 files.

## Bugs fixed

1. **`statement.extract_table_name` read mssql bracket-qualified names as
   garbage** (`lua/poste-db/statement.lua`) — `FROM [dbo].[users]` had its
   leading `[` stripped, then split on the first dot, leaving the second
   part as `[users`. The quote strip now runs again after the schema
   split. Bare `[users]` already worked and is pinned alongside.

2. **Table-name extraction truncated the last multi-line statement to its
   first line in cursor mode** (`sql_runner/response.lua`) — the
   multi-result path passed `visual_sel_end`, which is nil for cursor
   runs, and `get_stmt_sql`'s no-max_end default (`stop = start`) then
   chopped the statement after line one: a two-line
   `SELECT * FROM\nusers;` lost its FROM clause and rendered with
   `table_name = nil`. The call now falls back to `deps.stmt_end` (added
   to `response_deps`) then `#deps.buf_lines`, matching the error path
   at line 115. `get_stmt_sql`'s truncation semantics stay as-is and are
   now pinned by a spec case so the next reader knows callers must pass
   `max_end`.

3. **`ops_sql.build_alter_column_sql` had the defect the 09-18 pass fixed
   in table_ops** (`db_browser/ops_sql.lua`) — the generic branch emitted
   pg's `ALTER COLUMN c TYPE t` for mssql (no `TYPE` keyword; inline
   DEFAULT is also illegal there), clickhouse (needs `MODIFY COLUMN`) and
   sqlite (cannot alter types in place at all). The generator now
   branches per dialect like `table_ops.gen_alter_type`: clickhouse
   `MODIFY COLUMN` + `COMMENT COLUMN`, mssql bare `ALTER COLUMN` with the
   DEFAULT carried as a review comment, sqlite guidance comments only.
   The postgres branch also schema-qualifies through
   `qualified_table_ref` (the generated ALTER no longer depends on the
   session `search_path`; the mysql branch picks up its backtick
   quoting).

4. **`copy_ddl.prepare_table_ddl` interpolated the table name into gsub
   patterns unescaped** — a MySQL backtick-quoted name with gsub-magic
   chars (`order-2024(`) errored or mis-matched. `vim.pesc` on the
   pattern side, `%`-doubling on the replacement side.

5. **`snippets.get_completion_items` crashed on a pattern-magic prefix**
   — the typed prefix was interpolated into a `find` pattern, so
   completing after `sf(` raised "malformed pattern". Plain find now.

6. **`ident.quote_literal` did not escape backslashes for clickhouse** —
   ClickHouse treats `\` as an escape character inside single-quoted
   literals, so a literal backslash would corrupt the value. (The
   function is currently test-only in this repo; fixed as the shared
   quoting utility.)

7. **Cleanup** (`import.lua`): the `skip` action's `rows_to_import`
   reassignment was a no-op (valid_rows never contained the rejected
   rows) and the `execute_import` callback was an empty `if` under a
   luacheck waiver — both removed; `execute_import` reports its own
   success/errors.

## Recorded, not changed (with rationale)

- **`get_stmt_sql` truncates the last statement without `max_end`** —
  pinned by spec since this pass; every production caller now passes a
  bound, but the default remains a trap for new callers.
- **Import error numbering uses two different spaces in one dialog** —
  validation errors report the CSV file line (header = line 1; pinned by
  `sql_import_mapping_spec.lua`), chunk execution errors report 1-based
  data-row numbers. Both are individually defensible; a mixed-severity
  import shows rows that disagree. Unifying would change pinned
  expectations — left for a deliberate UX pass.
- **`coerce_value` maps an empty cell to nil and validation only guards
  PK columns** — a NOT NULL non-PK column with an empty CSV cell passes
  validation and fails at the server; the preview does flag those
  columns in orange (nullable, non-PK, no default) by design.
- **`diagnostics.lua` shares one debounce timer across buffers** —
  switching buffers within 300 ms cancels the previous buffer's pending
  update, and `BufLeave` clears diagnostics that `BufEnter` only
  restores after the debounce. Staleness window, not a correctness bug.
- **DDL generators omit the schema prefix for non-postgres dialects**
  (`table_ops.lua` and `ops_sql.lua` alike) — mssql `[schema].[table]`
  and clickhouse `database.table` would be more correct than the bare
  quoted name; postgres is handled.
