Round 44, following `docs/REVIEW-2026-09-28.md`. Scope: the modules the
spec-coverage sweep had never reached (`db_browser/copy_progress`,
`ops_drop`, `yank`, `db_browser/util`), then the delivery seams those

Baseline: 1894/0. Final: **1911 Success / 0 Failed / 0 Errors**

## Fixes (each with tests)

- **A run that never started reported its failure twice — or not at all.**
  `exec_run.run_async` delivered `on_error("Poste binary not found")`
  itself and returned `nil` — and every caller's own
  `if not job_id or job_id <= 0` armor turned that nil into a second
  failure report (double toasts in `sql_conn.run`, `executor.execute`,
  `db_browser/util.run_ddl_and_refresh`; in `ops_drop`'s batch drop, a
  double `failed` count **plus a second `process_next(idx + 1)`** that
  re-processed the following item). The opposite fault existed for a
  `jobstart -1` (binary present, spawn refused): no callback fires at
  all, so `import/execute` — the one caller that ignores the return —
  waited forever. The seam now owns the delivery: a failed start
  reports `on_error` exactly once and returns `1` ("handled inline",
  the value a lone USE already returned); the synthesized `on_exit(-1)`
  a failed start produces stays swallowed behind a `start_failed` flag
  (same defect family the redis repo fixed yesterday). Callers' id
  checks remain as dormant armor; a follow-up sweep may remove them.

- **A blank statement parked the session forever.** `executor.execute`
  dispatched an empty or whitespace-only statement at the session
  transport — whose binary classifies it Blank (`parse_request` trims,
  then skips without any wire event; verified live) — leaving the
  request in `session.pending` forever. exec-file answers the same
  input with "No SQL statements found". Reachable from `sql_runner`,
  where a statement span of blank lines makes `stmt_sql_raw = ""` (an
  empty string is truthy in Lua, so the session-routing check passed
  it). The guard at the executor seam gives both transports one
  immediate "Empty SQL statement" verdict.

- **The copy/drop error summaries split CJK glyphs.** Both dialogs
  chunked error text on raw 50-byte boundaries — server errors
  routinely carry CJK, a byte landing inside a 3-byte glyph printed
  U+FFFD — the same class the byte-budget round fixed in four other UI
  surfaces; these were the survivors. Shared
  `db_browser.util.wrap_utf8` backs the cut up over continuation bytes
  (and keeps a glyph whole when the budget is smaller than one). The
  summaries also listed errors in `pairs()` order, which reshuffles
  between runs — the pickers got the sort treatment two rounds ago.
  A non-string error no longer raises on `:gsub`, and the progress
  bar's `filled` count carries the `total > 0` guard its `pct` twin
  already had (the byte-cut family, third sighting: the redis panel's
  yank preview got the same fix today).

## Audited, no bug (recorded because it looked like one)

- **The `summary` event carries the raw connection URL** (password
  included) on the wire. It looked like a leak against schema.md's "a
  message that quotes a resolved URL masks its password" — but that
  rule governs *messages*; the event is internal piping, and every
  consumer that displays or persists redacts (`format.lua` at both
  render sites, `sql_log` redacting on write). Changing the wire shape
  would be MAJOR for no visible gain. Verified through the whole Lua
  chain.

- **`results[label]` collisions in the progress dialogs**: two jobs
  with the same label (same table name pasted from two schemas;
  same-named triggers) overwrite one row in the dialog while the
  counters stay correct. Display-only distortion in an edge the
  conflict-naming pass already narrows; a fix needs a policy for which
  item keeps the clean label.

## Observed, left alone

- **`replace_database_in_url` splits at an unencoded `#`/`?` in the
  password** (Rust side) — the `--database` swap would land inside the
  userinfo. Those bytes are illegal there for real URL parsers too, so
  replace and connect fail consistently; only the unencoded-`/` shape
  (already handled by `mask_url_password`'s step 2) is worth code.
- **The `job_id <= 0` checks at eight call sites are now unreachable**
  after the failed-start contract fix. Dormant armor, not dead weight —
  but a future sweep should either delete them or re-point them at the
  contract doc.
