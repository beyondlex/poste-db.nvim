## Fixes (each with tests)

- **`nav_ui.build_statusline_context` type-gates the strings it renders**
  (`buffer/nav_ui.lua`). A numeric `connection` on a hand-built or
  schema-violating meta reached `conn:match` inside the winbar build and
  killed the whole dataset redraw (probed: `attempt to index local
  'conn' (a number value)`). `connection`/`database`/`table_name` now
  count as absent unless strings — the session-name path and URL
  extraction keep working, the entry renders without that fragment.
  The `vim.NIL` sentinel checks fold into the same gate.
- **`ai/system_prompt.build` treats non-string scope fields as absent**
  (`ai/system_prompt.lua`). The chat scope map is hand-buildable and
  `state.context` mirrors binary payloads; a number/table where
  connection belongs reached `string .. redact(x)` (`redact_url` passes
  non-strings through) and crashed the prompt build inside the chat
  request (probed). `dialect_of` also resolves once per build instead
  of three times.
- **The statement boundary bg follows Normal's darkness**
  (`statement_indicator.lua`). Two stacked problems: the row tint was
  hard-coded navy — on a light colorscheme that puts the theme's dark
  text on a dark row — and `setup()`'s first-run guard turned the
  ColorScheme re-apply in `init.lua` into a no-op, so a mid-session
  dark→light switch kept the navy. `setup()` now picks the bg via
  `util.is_dark_color` (dark navy / light blue tint), re-runs cleanly,
  and the help doc records the behavior.
- **The context menu's lowercase shortcut alias finds its item**
  (`db_browser/context_menu.lua`). The alias binding for an uppercase
  item (`N`, `T`, `D`, `I`) bound the lowercase key but looked the
  LOWERCASE letter up in the item map, where no item ever lives —
  pressing `n` next to "[N] Create Database" was a silent no-op.
  `shortcut_keys()` resolves the alias to the original letter and only
  takes the key when no other item uses it (the table menu's `i`/`I`
  pair keeps `i` on INSERT).
- **`insert_hint.update` ignores a non-current buffer**
  (`insert_hint.lua`). CursorHold passes the SQL buffer explicitly, but
  the handler can fire after the user switched windows; the recompute
  then pairs the other window's cursor with this buffer's lines and can
  park a bogus extmark. Now a no-op when the buffer isn't current —
  returning fires CursorMoved, which recomputes anyway.
- **`copy_progress` finds the success label before subtracting from it**
  (`db_browser/copy_progress.lua`). `done_line:find(...) - 1` would
  crash on `nil - 1` ahead of the nil guard if the label text ever
  drifts. Not reachable today (the line is built from the same
  variable), fixed for shape.
- **Every close of the paste-confirm dialog counts as an answer**
  (`db_browser/copy_progress.lua`). `on_cancel` was part of
  `show_paste_confirm`'s contract but only the `n` key fired it —
  `q`, `<Esc>` and a WinLeave closed the dialog without answering, so
  a caller relying on the callback for cleanup would silently leak.
  All four paths now run through one settle guard (y confirms once,
  everything else cancels once, the close-triggered re-entry is
  absorbed instead of stacking a second answer); the only current
  caller's cancel branch is an empty stub, so this is a latent trap
  closed, not a visible behavior change.

## Change

- **`perf(statusline)`: the per-connection ctx highlight is cached per
  fingerprint** (`statusline.lua`). `get_ctx_color` runs on every
  statusline evaluation and cursor move, and `nvim_set_hl` forces a
  full-screen redraw even when unchanged. The definition re-applies
  only when the connections.toml fingerprint (color/link/bg) changes;
  ColorScheme bumps a `vim.g` epoch that every cached entry is stamped
  with, so stale entries re-derive. This is the poste-redis sibling's
  round-24 cache ported over so the two stop drifting — and the port
  fixes a second drift: a color naming a nonexistent highlight group
  falls back to a literal fg instead of linking to nothing
  (`pcall(nvim_get_hl)` succeeded on the empty table the API returns
  for a missing group). Tests pin the fp update and the ColorScheme
  re-derivation, including across a module reload.
- **The reload hazard the cache work uncovered** (LEARNINGS #20): this
  Neovim silently dedupes autocmd registrations whose callbacks are
  content-equivalent, so a reloaded module can never get a second
  handler. The redis sibling's identical cache still has the upvalue
  form — same latent staleness after any spec-driven reload — worth
  porting the epoch there.
- `autocmds.lua` hoists the byte-identical `setup_db_browser_keymap`
  copies out of `setup()`/`setup_existing_buffers()`.
- `buffer/nav_ui.lua` drops `shorten_select_fields`' dead `width`
  parameter (never read by the body).

## Read, not changed (recorded on purpose)

- **`config.lua`'s `sql_table_ops` key names are misnomers** —
  `select_all`/`refresh_all`/`describe_all`/`toggle_menu` actually bind
  Add column / Rename column / Drop column / Alter column type
  (`table_ops.register_keymaps`). The names are leftovers from an older
  iteration; the doc-poste keymaps page describes the real behavior.
  Renamed keys would break user overrides for zero functional gain, so
  the names stay — read the `desc`, not the key.
- **`completion/handlers`' pending-counter never times out** — if a
  `data.ensure_*` fetcher never calls back, the completion callback
  never fires. That is the fetchers' contract (`start_introspect_job`
  always answers), and a timeout here would race the real answer.
- **`copy_progress.start_copy` runs jobs strictly sequentially** — by
  design: the progress dialog's contract, and parallelism would
  multiply server load for no UI gain.
- `indicators.lua`'s shared spinner timer and per-line sign tracking
  are correct as documented (a per-line timer would freeze earlier
  spinners).
