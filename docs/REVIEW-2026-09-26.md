## Fixes (each with tests)

- **`insert_hint` cut `--` comments out of string literals**
  (`b303fc7`). The comment strip was a blind `gsub("%-%-.*", "")`, so
  `VALUES ('http://x--y', 7)` lost `--y', 7)`, the quote stayed open, the
  value separator count derailed and the highlight pointed at the wrong
  column. Stripping is now quote-aware (standard `''` doubling).
- **`insert_hint` mapped multi-line column lists one byte left**
  (`b303fc7`). `to_buf_pos` returned 1-based columns for the statement's
  first line and 0-based ones for later lines, while the buffer-column
  arithmetic assumed a single convention — any INSERT whose column list
  did not start on line 1 highlighted ` nam` instead of `name`. All
  positions are 0-based now; an offset landing on the joining newline
  maps one past the previous line's end (an empty segment the search
  skips).
- **`insert_hint` kept hinting past the VALUES close** (`b303fc7`). The
  past-the-close guard compared a 0-based offset with a 1-based index
  using `>`, so the hint lingered while the cursor sat on the closing
  paren or the trailing `;`. It is `>=` now.
- **`insert_hint` autocmds moved to FileType** (`b303fc7`). The `*.sql`
  filename patterns missed every buffer without a `.sql` name (an
  unnamed scratch buffer got no hints at all); the hooks now attach
  per-buffer from `FileType poste_sql/poste_sqlite`, matching the family
  convention. `update`/`clear` take an explicit buffer.
- **Byte-budget truncation split CJK glyphs in four UI surfaces**
  (`8e900c5`). `file_exec.fmt_sql` (history lines), `dml_guard.snippet`
  (confirm dialogs), `statement` labels and the DB-browser flash float
  all cut with `sub(1, max)` on byte counts: a Chinese comment or
  literal put the cut inside a glyph, and byte-measured text overflowed
  its screen budget by up to 3x. New `util.ellipsize(s, max)` budgets
  display cells via `width.truncate` and appends `...` only when it
  actually cut; all four sites (plus the flash float's width math) go
  through it.
- **The sql_sql_runner util stub needed forwarding** (`25ba668`). The
  spec stubs `poste-db.util` with `{}` to isolate the runner; dml_guard
  is a transitive dep and calls `util.ellipsize` in its confirm path, so
  the gate turned every DML-guard rejection into "attempt to call field
  'ellipsize' (a nil value)" while targeted runs stayed green. The stub
  forwards the real helper — a note for every future isolation stub:
  list what your transitive deps call.
