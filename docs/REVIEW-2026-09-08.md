## Bugs fixed

1. **CTE-wrapped writes bypassed the AI SQL confirm gate** (`ai/actions.lua`)
   — `is_readonly` classified every statement starting with WITH as
   read-only, but Postgres and SQLite accept
   `WITH del AS (DELETE FROM t RETURNING *) SELECT * FROM del`:
   the destructive statement executed without any confirmation. A WITH
   statement is now read-only only when it contains no whole-word
   INSERT/UPDATE/DELETE/MERGE/REPLACE. The boundary classes are
   underscore-aware (`%f[%w_]…%f[^%w_]`) because Lua's `%w` excludes `_` —
   without that, a column named `last_update` would trip the scan. A false
   positive (write word inside a string literal) only costs an extra
   confirmation — the safe direction.

2. **SQL session pool keyed on the bare connection URL**
   (`session_conn.lua`) — `M.get(conn_url, bufnr, database)` reused an
   existing pooled session regardless of the requested `database`, so a
   second buffer (or a later execution) using the same connection with a
   different `@database` directive **silently executed against the wrong
   database** and labeled the results accordingly; `SET`/temp-table state
   leaked the same way. The pool key is now `conn_url .. "\0" .. database`,
   so each pair keeps its own warm session. `:PosteDbSessionStop` accepts a
   bare URL (closes every database-scoped session of it) or an exact key;
   `:PosteDbSessionList` shows the database per entry.
   Tests: new `tests/sql/sql_session_conn_spec.lua` (pair pooling, stop by
   URL, per-database dispatch).

3. **Schema cache never re-used cached column lines** (`ai/schema.lua`) —
   `expand_and_render` marked only *newly introspected* tables as expanded,
   so a table mentioned a second time rendered as the one-line
   `- name (comment)` form even though its column line sat in the cache —
   defeating the cache's purpose and contradicting the docstring. Cached
   tables named in the text are now seeded into `expanded` before the
   candidate scan (and `MAX_EXPAND` is no longer read through the `_test`
   hook from production code).
   Test: ai_schema_spec "re-uses cached column lines when a table is
   mentioned again".

4. **TOML basic-string escapes were applied as sequential gsubs**
   (`toml.lua`) — a later gsub re-processed characters produced by an
   earlier one: `"D:\\tables\\notes"` (raw TOML) ended up with a literal
   newline for the `\t` of `\tables` and the `\n` of `\notes` — any Windows
   path whose folder names start with n/t/r/b/f was mangled. Unescaping is
   now a single pass with a lookup table; unknown escapes stay verbatim.
   Tests: sql_toml_spec path/`\new`/unknown-escape cases.

## Recorded, not changed (with rationale)

- **`is_readonly` still blanket-trusts `pragma`** — `PRAGMA journal_mode=wal`
  writes, but pragmas are dialect-specific and the confirm heuristic is
  documented as such; gating every PRAGMA would nag SQLite users for the
  common read cases. If it ever matters, special-case the known write
  pragmas.
- **`database_from_url` returns the sqlite query suffix** (`file.sqlite?mode=rwc`)
  as the display database — cosmetic; it only feeds fallback display/`--database`
  (which the sqlite session ignores). Not worth a parser.
- **`ai/mentions.lua` `cached_list` never invalidated** — new connections.toml
  entries need a session restart to appear in `@`-completion; deliberate
  cache, documented in the module.
- **tests/ tree carries ~49 luacheck warnings** (CI gates `luacheck lua`
  only). Mostly unused locals in fixtures; not touched this round.
- **`dml_guard` TS→regex fallback, `toml` dotted headers, cursor
  dual-source** — carried unchanged from the 09-07 report.
