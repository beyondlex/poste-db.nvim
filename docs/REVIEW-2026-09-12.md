# Code Review — 2026-09-12

Follow-up to `REVIEW-2026-09-06/07/08/09/11.md`. Scope: the modules the
earlier rounds had not put under a fresh pass — `log_viewer.lua`,
`import/{format,mapping,execute}.lua`, `editor/{cell,column,nav}.lua` —
plus pattern sweeps (byte-slicing, keyword substring checks, and-or
truncation, job-output handling) over `buffer/`, `db_browser/`,

## Bugs fixed

1. **CJK names corrupted the history summary rows** (`log_viewer.lua`) —
   the table/db column truncated with byte-based `sub` and padded by byte
   length: a name wider than the column cut a multibyte character in half
   (invalid UTF-8 in the buffer) and CJK rows visually overflowed the
   layout. Widths are now display-width based with a shared char-safe
   `fit_width` (same approach as format.lua's `wrap_text` from 09-11).
   `apply_highlights` also derived extmark offsets from fixed arithmetic
   that assumed a 15-byte timestamp (actual: 14) and a db segment of
   exactly `TBL_W` bytes — both drifted for multibyte names; the summary
   segments now come from one `summary_parts()` shared by render and
   highlight, offsets computed from the real byte lengths.

2. **TSV import dropped empty edge cells** (`import/format.lua`
   `parse_tsv`) — each raw line was trimmed before splitting on tabs, so a
   leading/trailing empty cell (`a\tb\t`) lost its column: mixed rows
   failed with a spurious "expected N columns, got 2", and imports where
   every row shared the empty edge cell silently shifted the column
   mapping. Rows now split raw; only blank lines are skipped.

3. **`NULL`/`true`/`false` literals matched only two spellings**
   (`import/mapping.lua` `coerce_value`) — all-lower and all-upper matched
   but `null` (JSON tools), `Null` (report exports) and `True`/`False`
   (Python's csv module) stayed strings. Matching is now case-insensitive,
   consistent with column types (already lowercased). Coercing boolean
   literals regardless of column type remains the documented design
   (pinned by the existing spec).

4. **JOIN edit guard tripped on `join_date` columns** (`editor/cell.lua`
   `has_join`) — a bare substring find also matched column names like
   `join_date`/`joined_at` and any string literal containing "join",
   blocking cell editing with a bogus "multi-table (JOIN) queries" warning.
   Same literal-substring class as the 09-11 Rust RETURNING fix. JOIN now
   matches on identifier word boundaries (`[%w_]` — Lua's `%w` excludes the
   underscore SQL identifiers use) outside quoted literals. The divergent
   duplicate in `editor/column.lua` (whitespace-before-only check, no
   literal blanking) is removed; `editor.has_join` re-exports the cell.lua
   implementation the edit guard actually uses.

5. **AI context truncation split multibyte characters** (`ai/mentions.lua`,
   `ai/schema.lua`) — the 12000-byte schema-summary cap and the 6000-byte
   context cap cut with a bare byte-based `sub`, landing mid-character for
   CJK schemas and sending invalid UTF-8 to the provider. Both now use the
   new `util.utf8_safe_cut` (backs the boundary off continuation bytes).

## Recorded, not changed (with rationale)

- **`extract_table_name` counts a "join" inside a literal**
  (`statement.lua`) — one real JOIN plus a literal containing "join"
  reaches `join_count >= 2` and returns nil, falling back to the "result n"
  label. Conservative failure direction (label only, not execution);
  fixing properly means duplicating the blanked-literals view in Lua.
- **`USE` detection requires a plain identifier** (`sql_runner.lua`,
  `statement.lua`) — `USE \`my-db\`;` / quoted or hyphenated names don't
  match `[%w_]+` and route into the session instead of switching. Carried
  from 09-09 (which fixed the lowercase case); hyphenated db names are rare
  and the failure mode is a session-mode error, not silent wrongness.
- **`coerce_value` leaves a fractional value for an INT column as a
  string** — deliberate pass-through to the DB's own error, already pinned
  by a spec ("change deliberately, not silently").
- **`check_table_exists` formats the name into the SQL literal**
  (`db_browser/copy.lua`) — names come from introspection, not free user
  input; a quote-bearing object name would need escaping but cannot be
  typed into the paste dialog without also failing earlier.
- **`db_browser` paste conflict check is per-object sequential** — fine at
  real-world paste sizes; batching would complicate the progress dialog
  for no measurable gain.
- Carried unchanged from 09-11: JSON export loses duplicate column names;
  `resolve_connection_url` sqlite `?mode=rwc` with an existing query
  string; `os.rename` semantics on Windows; minimal toml.lua;
  NULLs-last sort; plenary single-spec invocations flaky.
