## Bugs fixed

1. **The export command completion answered for the argument one slot
   early** (`export.lua`, commit `ca6cfaa`). The word count included the
   command name, so vim's real mid-word call (`:PosteDbExport cs<Tab>`
   arrives as `complete('cs', 'PosteDbExport cs')`) read the format slot
   as the destination slot: `cs` matched nothing, and a one-letter lead
   completed `clipboard` INTO the format argument, which the run then
   rejects as "Unknown export format 'clipboard'". Tab after a
   terminated format fell through to filename completion. The argument
   number is now word count minus the command name, bumped by a trailing
   space. The old no-trailing-space pin contradicted how vim passes
   ArgLead and is gone (replaced by the mid-word / trailing-space /
   path-fallback specs).

2. **JSONB cells searched and filtered as pointer text** (`buffer/search.lua`,
   commit `94dcf99`). A JSON/JSONB cell arrives decoded as a Lua table; the
   renderer, the yank and the exporter compact-encode it, but
   `compute_matches` matched against `tostring(val)` — a `table: 0x…`
   address. Searching for text visibly inside a JSONB cell answered "No
   matches" while the cell displayed exactly that text, and
   `filter_by_current_cell` compared with `==` (pointer identity), so
   filtering kept only the row the filter was taken from even when other
   rows held identical JSON. `search_text_of` gives both the display form;
   `same_value` compares tables by encoded form and keeps plain `==` for
   scalars.

3. **Width-spelled and modifier-wrapped binary types read as editable**
   (`editor/cell.lua`, commit `eafab12`). `is_editable_field` checked the
   ineditable set by exact name; MySQL introspection spells widths
   (`varbinary(16)`, `bit(1)`) and ClickHouse wraps modifiers, so those
   binary columns were offered as editable text and the commit failed only
   at the server. The check now reads the root word of the unwrapped name —
   the same lookup `validate_value` already asks via `types` — and the line
   stops assuming ctype is a string.

4. **A hex-spelled port string resolved through LuaJIT's hex tonumber**
   (`connections.lua`, commit `868bdef`). `tonumber("0x10")` — even with
   base 10 — is 16 on LuaJIT, so a quoted `port = "0x10"` typo built
   `postgres://h:16/d`: the wrong server, no error anywhere, while the Rust
   mirror (f64 parse) refuses the same file. Port strings now read through
   the decimal grammar the Rust side parses; numbers pass unchanged (the
   float-port pin from round 59 untouched).

## Probed, held (recorded on purpose)

- `compute_view_indices` with a NaN in a numeric column: NaN compares
  "equal" to everything (`a < b` false both ways), which is not a strict
  weak ordering — LuaJIT's `table.sort` may raise "invalid order function"
  on adversarial row counts. Unreachable through the transport today (JSON
  has no NaN; non-finite doubles arrive as text), so no guard was added;
  revisit if a value path ever produces Lua NaNs.
- `import/format.parse_json` on an array of arrays (`[[1,2],[3,4]]`)
  imports with numeric column names `1`,`2`. Nonsense but visible in the
  mapping UI; erroring instead might break a paste that today half-works.
  Held.
- `editor/cell.parse_value("5.0")` on an integer column returns the STRING
  `5.0` (the precision-preserving path) and `validate_value` refuses it —
  "Cannot assign string to integer column". Strictness is right (SQL would
  coerce), but the message names a string the user never typed as such.
  Held; revisit if the wording confuses.
- Search matching is ASCII-case-folded (`string.lower`): `Ä` does not match
  `ä`, in the dataset search and the grid search alike. A Lua-runtime
  limitation, both sides consistent. Held.
- `editor/cell.track_cell_edit` compares old/new with `==`: a JSONB cell
  edit reverted to identical JSON still counts as dirty (separate decodes
  are separate tables) and the commit prompt stays. Harmless — the write
  is idempotent. Held.
