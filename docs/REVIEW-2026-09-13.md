## Bugs fixed

1. **`%` in a connection name killed every statusline redraw**
   (`statusline.lua`) — the legacy inline mini wiring and
   `get_context()`/`fmt_ctx` baked the raw context string (`conn/db`,
   names from user-authored `connections.toml`) into statusline markup; a
   literal `%` makes every redraw fail with `E539: Illegal character`
   (same verified class as the poste.nvim fix this round). The shared
   `poste.statusline` path already escapes since poste.nvim's `markup()`
   does it; the legacy fallback and lualine-adjacent `get_context` are
   covered now, with `nvim_eval_statusline` regression tests.

2. **CJK result values sent invalid UTF-8 to the AI provider**
   (`ai/init.lua` `ask_resultset`) — result-set cell values were cut with
   a byte-based `sub(1, 57)`: any CJK value (the norm in Chinese schemas)
   split mid-character. Exactly the class fixed in 09-12 for
   `ai/mentions`/`ai/schema`; this instance survived that sweep. Cells now
   go through `util.utf8_safe_cut`. The regression test uses a value whose
   57-byte boundary lands *inside* a character, so the old code fails it.

3. **CJK table names misaligned the db-browser context menu box**
   (`db_browser/context_menu.lua` `build_menu_lines`) — width and the top
   border's `─` padding were computed from byte lengths (`#title`), so a
   CJK name drew the top border shorter than the bottom one (each CJK char
   counts 3 bytes but 2 columns). Widths are display-based now; identical
   output for ASCII names.

4. **Completion debug view split CJK column comments**
   (`completion/debug.lua`) — documentation text was cut with
   `sub(1, 55)`; column comments (the usual doc source) are often CJK.
   Same `utf8_safe_cut` treatment.

## Carry fixes (same day, later)

Ledger sweep against all REVIEW-2026-09-*.md: the first-tier carries are
fixed now, with regression tests.

- **`USE` with a hyphenated db name** (`exec_run.detect_use`,
  `sql_runner.is_use_stmt`) — `[%w_-]` accepts `USE my-db;` /
  `` USE `my-db`; `` so it switches context instead of reaching the session
  as real SQL (carried from 09-09/09-12).
- **`extract_table_name` "join" inside a literal** (`statement.lua`) —
  single-quoted literals are blanked (length-preserving, `''`-escape aware)
  before the JOIN count; double-quoted regions stay (identifiers).
- **sqlite `?mode=rwc` with an existing query string** (`connections.lua`
  `build_conn_url`) — `f.db?cache=shared` gains `&mode=rwc`; an explicit
  `mode=` is left untouched (carried from 09-11).
- **`database_from_url`** (`session_conn.lua`) — query strings are stripped
  (sqlite `?mode=rwc` suffix, `?schema=public`), and a db-less URL with a
  `/` inside the password returns nil instead of leaking `p/ss@h:3306`
  (carried from 09-06/09-08).
