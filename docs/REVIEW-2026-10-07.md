## Bugs fixed

1. **`SELECT u.name,o.total` navigated to column `o`** (`nav/detect.lua`,
   this round's first commit). The `dot_column` and `insert_column` branches
   read the column after the cursor by scanning the next `[%w_]+` past
   `end_col` unconditionally, so with the cursor on `name` in the common
   no-space-after-comma style, the scan jumped the comma and stole the next
   select item's alias (`o`) — go-to-definition landed on a column that does
   not exist in the resolved table. The word after the dot is only the
   target column when the cursor sits on the ALIAS side and a dot
   immediately follows the word; the third branch (`column`/`keyword`) had
   that `nxt == "."` guard all along, the first two did not. Pinned by 3
   tests in `sql_nav_detect_spec` (4 → 9).

2. **A JSON-null table-list entry crashed the Tables float**
   (`introspect/helpers.lua`). `build_table_lines` concatenated
   `item.name`/`item.type` raw; `run_json_items_job` never `clean_nil`s, so
   a binary entry with `"type": null` (vim.NIL) or a missing name raised in
   the notify path. Names fall back to a placeholder row, non-string types
   lose the `(type)` suffix. Pinned by 2 tests in
   `sql_introspect_helpers_spec`.

3. **`show_column_info`'s nil guard sat after the quote strip**
   (`introspect/column.lua`). The empty-table-name check was line 11; the
   `table_name:gsub(...)` that crashes on nil was line 9 — the guard could
   never catch its own case. Guard moved first. Pinned by a test in
   `sql_introspect_column_spec` (2 → 3).

4. **goto-definition reported a real connection as missing**
   (`nav/handlers.lua`). `find_connection_target_line` matched a byte-exact
   `^[name]`, but the round-56 parser fix accepts whitespace-padded quoted
   headers (`[ 'my db' ]`) — the very jump that points at such a connection
   said "not found in connections.toml". The finder trims and strips one
   MATCHING quote pair, with the round-56 lookalike rule (a lone quote is
   part of the name). Pinned by 2 tests in `sql_nav_handlers_spec`.

5. **An empty `<cword>` told the user to add a `@connection` header**
   (`nav/init.lua`). `resolve_definition_route` returns nil ONLY when the
   cursor word is empty (both directives and the table word return
   earlier), but the nil branch repeated the "No connection context. Add --
   @connection <name>" message copied from context resolution — advice that
   cannot fix the cause, and contradicted by `introspect/init.lua`, which
   says "No word under cursor" for the same situation. The message now
   names the real cause.

## Deduplication (DRY)

- **`util.unquote_ident`** — `introspect/context.lua` stripped identifier
  quotes before matching detect names; `nav/detect.lua` consumed the SAME
  `context detect` JSON with no strip, and leaked the source spelling
  (`` `posts` ``) into navigation targets. One helper now does it with the
  round-56 matching-pair semantics (the old `strip_q` shaved ANY end quote,
  so `` `users `` became `users`). Verified against both locally built
  binaries: today's `context detect` answers with bare names already, so
  both strips are defensive — the point is a future quoting binary cannot
  break the two sides unevenly. Pinned by 2 tests in `sql_nav_detect_spec`
  and 3 in `sql_util_spec`.
- **`util.scan_word_end`** — the "extend the cursor column over the
  identifier" loop lived twice (`introspect/init.lua`, `nav/handlers.lua`);
  the handlers copy also fed `extract_sql_block` one line read while
  measuring length against another. One read, one helper.
- **`context.detect_command`** — three call sites assembled
  `{binary, "context", "detect", offset, --dialect?}` with three different
  append rules (completion skipped `generic`, nav/introspect spelled it
  out). The builder in `context.lua` owns the flag contract; the two sync
  sites use it, completion's async pipeline can adopt it later. Pinned by a
  test in `sql_context_spec`.

## UX / performance

- The synchronous `context detect` inside go-to-definition (both
  `nav/handlers.lua` and `introspect/init.lua`) blocked the editor with a
  5000ms timeout while completion runs the same subcommand per keystroke
  at 2000ms. Both now follow the 2000ms precedent — a wedged binary freezes
  the UI for the same bound completion accepts.
- `db_browser/statusline.lua` carried an if/else whose branches called the
  identical setter with the identical value (empty statusline IS the reset);
  collapsed.
- `introspect/init.lua` re-declared `buf`/`cursor`/`line_num`/`line_text`
  inside `show_table_ddl` and hid the shadowing behind a file-wide
  `luacheck: ignore 411`; the ignore is gone, the re-reads with it, and the
  inline `require("poste-db.context"/"poste-db.connections")` calls became
  the top-of-file locals the rest of the file already uses.
- `nav/route.lua`'s `resolve_definition_route` used one of its five
  parameters; the signature is `(line_text)` with the current-window
  `<cword>` dependency stated where it can be read.

## Probed, held (recorded on purpose)

- **`resolve_detected_table_target` returns nil when `tables` is empty**
  (`nav/detect.lua:108` guard) — an INSERT-context response without a
  tables frame falls through to `handlers`' `navigate_to_table(cword)`,
  treating the COLUMN word as a table name. Whether the binary ever
  answers INSERT without a tables frame is unknown from the Lua side
  (verified the stock and poste-for-db debug binaries both answer bare
  names for the FROM-clause shapes; no INSERT probe binary-side). Watch,
  don't guess.
- **`detect.build_detect_payload`'s bracket guard is unreachable** —
  `find_block_for_line` always returns `block_start <= line_num <=
  block_end`, so `block_start > line_num or line_num > block_end` never
  fires. Harmless; left as cheap insurance for future edits to the block
  scan.
- **`introspect/exec.lua` shows items AND notifies on a non-zero exit with
  parseable stdout** — deliberate per the in-file comment (buffered stdout
  survives a failed run); `journal_once` dedupes the two journal paths, so
  the log keeps exactly one entry.
- **`introspect/job.lua` `append_stderr`'s `log_prefix and require(...) or
  nil`** — works (require always returns truthy), merely cute; not churned.
- **`ai/init.lua` `ask_resultset`** truncates to 20 rows, flattens `|` and
  newlines, and cuts 60-byte cells with `utf8_safe_cut` — re-driven with a
  CJK cell, no invalid UTF-8, all good.
- **`buffer/render.lua`'s `data_start_line - 3` arithmetic** is load-bearing
  and obscure (header + its two neighbors removed, then re-padded and
  shifted); `sql_buffer_render_spec` pins it, so it stays.

## Suspected, unverified (recorded for a blink.cmp source check)

- **`db_browser/completion.lua` `cleanup()` only restores
  `cfg.completion.enabled` when the saved original was non-nil**
  (`_orig_enabled ~= nil` guard). If `enabled` can legitimately be nil in
  whatever `adapter.get_config()` returns, the patched closure

  which of the two holds needs the blink.cmp source, and this repo has no
  specs over that seam (0 test references). Left untouched on purpose.

## Architecture smells (recorded, not acted on)

- **Two `pick_table_match` siblings remain** (`nav/detect.lua`,
  `introspect/context.lua`): both strip quotes via `util.unquote_ident`
  now, but the introspect one skips SKIP_KEYWORDS-named matches and the
  nav one does not (a table literally named `if` would match; none exists
  in practice, and nav's keyword gate sits one layer up if ever needed).
  One owner for "interpret a detect response" would end the pair — a
  candidate for a round with binary-behavior budget.
- **The two synchronous detect sites still each own their
  system/wait/decode/`clean_nil` tail**; only the argv builder is shared.
  A shared sync runner needs a home both `nav/` and `introspect/` already
  trust — held until one appears.
- **REVIEW logs accumulate under `docs/`** — carried from round 56, still
  true.
