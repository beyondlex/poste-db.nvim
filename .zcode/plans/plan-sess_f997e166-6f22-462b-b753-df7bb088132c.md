# 方案 C：收紧 poste.nvim 共享层

目标：消灭 "sibling 改共享层炸另一个 sibling" 的两条真实路径（statusline 全局表面、poste.state 互踩），并把共享契约固化成测试。结论依据：`poste.statusline` 的 pcall 与 `%` 转义已存在，缺的是注册校验与契约测试；`poste_state.current_env` 无人写（http 写的是自己的 state），唯一真实互踩是 `poste_state.connection`（redis 写+读、es 写）。

## 改动 1：poste.nvim — statusline 契约硬化
文件 `lua/poste/statusline.lua`：
1. `register_provider` 校验（name 必填、resolve 可调用），按 name 去重——插件重载时 re-register 替换旧条目而非堆积；新增 `M.unregister_provider(name)`。
2. `markup()` 加固：`ctx.text` 非 string 时跳过该 provider；`hl` 中的 `%` 同样转义（防同类 E539）。
3. 模块头注释补全 provider 契约：spec 字段、scope 语义（buffer > window > global，同 rank 先注册者优先）、hl 组归 provider 自有且按 `Poste<Plugin>Ctx*` 命名、resolve 必须廉价（compose 层每次重绘调用两次，memoize 在 provider 侧做——redis 已这么做）。
4. 不加 resolve 缓存（避免 staleness，契约文档代替）。

## 改动 2：poste.nvim — statusline 契约测试
新文件 `tests/poste/statusline_spec.lua`（沿用 `tests/run.sh` + `minimal_init.lua` 基建与 `tests/poste/` 现有 spec 风格，用 `M._test.reset`）：
- db 式 buffer-scope + redis 式 window/global 双 provider 共存：优先级与 tie-break 断言
- 单个 provider 抛错 → 其它 provider 正常渲染（pcall 隔离）
- provider 返回 nil / 非 string text → 跳过不炸
- 文本含 `%`（连接名 "100%"）→ 转义为字面量
- 同名重注册替换、unregister 生效

## 改动 3：poste.nvim — state 所有权规则 + 版本标记 + 死代码清理
1. `lua/poste/state.lua` 本身不改代码（`connection` 是动态挂载字段）；在 poste.nvim `AGENTS.md`（及 README/docs 如有相关章节）写明所有权规则：共享单例只提供 config、binary 解析、`current_env`（read-mostly，核实过无人写）等，禁止 sibling 动态挂可变字段。
2. 新增 `lua/poste/version.lua`（semver 常量）；AGENTS.md 写明 `lua/poste` 公开 API 的 semver 纪律：破坏性变更 = major + compat shim（参考 poste-db/compat.lua 模式）；sibling 用能力检测（现有 `legacy_mini_wiring` 模式）而非版本号比较。这是对"能否 pin 版本"的替代答案：rtp 单副本模型下 pin 不了，能做的是统一锁版本（lazy-lock.json）+ 稳定契约。
3. 删除零调用模块（已 grep 复核全生态 10 个仓库）：`lua/poste/state/event.lua`、`lua/poste/async/promise.lua`。

## 改动 4：siblings — 移除 poste_state.connection 互踩
- poste-redis.nvim `lua/poste-redis/connections.lua:366-368`：删除写共享 state 的 pcall 两行及注释。
- poste-redis.nvim `lua/poste-redis/browser/picker.lua:38-44`：`preferred` 改读自己的 `state.context.connection`（同义：本会话最后 apply 的连接）。
- poste-es.nvim `lua/poste-es/connections.lua:228-230`：同样删除写共享 state（es 无读取点，纯删）。
- 已知行为变化：es 里切换连接不再影响 redis picker 光标预置——本就是意外耦合。

## 改动 5：poste-db.nvim（本仓库）— 文档
- `docs/dev/sql/README.md` 与 `AGENTS.md` References 补链接：poste.nvim statusline 契约、state 所有权规则。
- 可选小步：db 侧补一个 provider 自测（非 db 窗口返回 nil）。
